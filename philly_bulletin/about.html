How it works · one city, every source

Make real life easier than the feed.

Reality is an events engine for one city. It reads every source — the venue calendars, the library feeds, the old HTML pages no aggregator touches — and turns them into one honest, ranked list of what is actually happening tonight. This page is the whole system, explained.

01 · The idea

The feed won. Build the counter-infrastructure.

Social media promised connection and delivered isolation. The loneliness epidemic is the symptom; the cause is that scrolling got easier than doing. Meanwhile the existing event platforms are lemon markets — Meetup, Eventbrite, and their imitators serve flat lists with no intelligence, while the best events in any city sit on old HTML sites, church bulletins, and local club pages that no aggregator captures. The bet: if you get people together in real life — genuinely, regularly, around things they care about — the downstream effects on loneliness follow.

We tried the app first, once. It failed the way consumer social apps fail: distribution, not concept. So this time there is no app store, no network-effects dependency, no growth loop. Intelligence first, product shape later. The engine has to be useful for person #1 on day 1 — one person, planning one week, in one city. Everything else is downstream of that.

02 · The enginefive layers, built bottom-up

Each layer stands on the one below it.

Nothing above layer 1 matters if the events are not real. So the stack is built in order, and each layer earns its own plan before a line of it exists.

1 · Events API — scrape, parse, and structure every event source in the city; the LLM does the reading 13 sources built
2 · AI ranking engine — an LLM scores each event: will you actually meet people, or just sit in an audience? scoring today's 42
3 · Personal context — a social-life file per person: friend CRM, goals, preferences, passions planned
4 · Action & coordination — suggest, invite (Luma / Partiful), sync calendars, learn what worked planned
5 · Community layer — tools for the person who always organizes things: coordinators, connectors, organizers future
03 · The org

Five roles, one-line charters.

The pipeline is run by agents with narrow jobs. The org chart is the pipeline: a lead moves left to right, and no role can skip another's gate.

SCORE Rater — runs the quality rubric, sanity-checks the ordering, tunes the weights 42 scored today●
Five charters, one direction of travel: lead → triage → build → keep-true → score.
04 · Honesty rules

Rules the pipeline can't break.

The UI is an honesty surface. Every page shows what the system actually did — verified-ago stamps, real counts, provenance — and nothing more.

  • Build gate — nothing is marked working unless it produced real events.
  • Honest downgrade — when a source rots, its status drops in public (■ needs repair), the day it happens.
  • Derived flags — monitored, coverage — are re-checked on schedule, never trusted stale.
  • Append-only scores — ratings accumulate; weights tune without rewriting history, and failures stay visible.
05 · The city

Why Philadelphia.

Because we live here, and an engine like this has to be useful for person #1 before it deserves a bigger city. The code is city-agnostic; the data is Philadelphia's — OpenDataPhilly's 159 official neighborhoods, the Free Library's feeds, the venue calendars of Fishtown and West Philly. Philadelphia is the workshop: build and prove the engine here, then point it at the next city without rewriting it.

06 · Colophon

The bet, and what came before.

The core technical bet is that LLMs are a phase change in text parsing: they can read a messy venue page, a church bulletin, or a library RSS feed and return the same normalized event — and they can judge quality (will you meet anyone here?) in ways keyword filters never could. If that bet is wrong, none of this works. So far it is holding.

Prior art: Ledge, an 80-endpoint Flask + iOS geospatial events app for Chicago. Concept right, distribution wrong — the lesson this whole system is built on. Its library scraper was the seed of layer 1.
